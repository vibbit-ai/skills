# Materials

There is no public material-library listing command. Use actual files, URLs, and resource IDs provided by the user or returned during this task. Browsing the account's cloud material library requires a supported interface or user-provided export; external search is not a replacement for it.

Assign meaningful roles to references and preserve their order. Do not generate or download assets just to satisfy a checklist. Record local identity and version when reuse matters.

For reusable talent, scenes, and scripts in the Agent, use the [private creative library](../workflows/creative-library.md) on local or host-provided persistent storage. Reading that library is not a cloud account-material query. Retain actual files/URLs and reference roles; a local photo-entry ID is neither a material ID nor a digital-human ID.

[Upload](../api/upload_info.md) can transfer a local file and produce an object URL. It does not register a material-library object; do not fabricate `material_id`. Upload only when a cloud step or the user's requested storage action needs it. See [media inputs](../runtime/media-inputs.md).
