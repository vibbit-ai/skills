# Reference adaptation

Use a reference's structure, rhythm, and expressive relationships to create the user's own script, shots, or video. For preservation of the actual source with people/objects/scenes replaced, use [1:1 remake](one-to-one-remake.md). Clarify only when the distinction changes the deliverable and context cannot resolve it.

Keep the user's explicit choices about what to retain and replace. A single camera/action reference can use supported generation directly without full analysis. Existing adapted scripts, storyboards, and media are the starting point. Planning-only requests end with planning.

## Choose and understand the relevant evidence

Use parsing/breakdown for script structure when needed, direct video references for appearance/motion, and editing for actual source replacement. There is no automatic editable-remake-project save contract. Do not promise identical pixels, frames, or performance.

For strict preservation, define observable requirements such as original audio, shot order, entry position, and action. Check whether controlled editing can satisfy them. If only an approximate generation is possible, explain the difference before presenting it as accepted 1:1 work.

Use [reference analysis](../creation/reference-analysis.md) to understand overall expression, element behavior, source times, and the words/actions those elements serve. Persistent boards, captions, and sound can cross shot boundaries.

Actual viewing/listening and available analysis support different claims. A transcript does not reveal expressions or camera movement; keyframes do not prove continuous motion. Preserve evidence versus interpretation.

Identify role relationships, opening/question, reveal/order/ending, synchronized speech/graphics/sound/cuts, and facts versus stylistic presentation. The reference product's price, efficacy, or testimonials do not become facts about the new product.

## Adapt the relationships

Track all manifestations of replaced identities: main performance, voice, portrait, B-roll, screens, and animation. For products, check handling, labels, and claims. Redesign behavior for the new subject while preserving useful humor, responses, and expressive purpose. Changing a name is insufficient if the action still serves the old topic.

For graphics, identify related state changes and events. Bind entry, emphasis, change, and exit to the new adopted words/meaning through [semantic timing](../creation/script-and-timing.md). The new selected audio determines actual times. Reference timestamps, average speaking speed, and segment ASR are not precise word evidence.

## Produce and revise

Use [talking heads](oral-broadcast.md), [short drama](short-drama.md), or [storyboard production](storyboard-video.md) according to the adopted design. Reuse current analysis rather than repeat it.

Validate the crucial replacement/action/audio-visual relationship before extending work when useful. Reference mode does not automatically preserve the original soundtrack or complete timing. Reuse real editable media instead of regenerating every frame simply because the request says remake.

For repeated production, use [project/run/receipt records](../contracts/production-plan.md). Adopt inspected exact artifacts and retain unaffected performance when only captions/graphics/sound change. Query unfinished tasks before submitting; the local planner cannot discover unrecorded account tasks.

Review the actual adapted meaning, accurate replacement, readable action, and preserved relationships through [video review](../capabilities/analysis/video-review.md). Similarity and server completion alone are insufficient.

Resume selected references, observation coverage, choices, script, shots, and task/results. New reference evidence updates affected judgments without retroactively claiming prior knowledge. “Not like the reference” should become a specific difference in sequence, action, composition, pacing, or sound. Caption/music/edit-point changes usually belong to postproduction. A changed reference requires reviewing affected dependencies, not discarding all work.

Deliver source references, analysis, and new media with their actual status; usable media is not proof of a saved platform project. For a Meta adaptation, use VB-04 or VB-07 only when the creative or market task calls for it.
